# Security Policy

## Supported versions
Security fixes will be documented in release notes after public releases begin. Until then, the project is in development and no formal support window is guaranteed.

## Reporting a vulnerability
Do not publish exploitable security details in a public issue.

Use a private GitHub security advisory if private vulnerability reporting is enabled. Otherwise, contact the repository maintainer privately through the contact method listed on their GitHub profile.

Include the affected version/commit, impact, reproduction steps, and any suggested mitigation. Do not include real user records, credentials, tokens, CAPTCHA secrets, or sensitive production data.

We will acknowledge reports when possible and coordinate disclosure after a fix or mitigation is available.
